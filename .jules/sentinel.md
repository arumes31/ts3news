## 2026-08-02 - Missing Global Security Headers Middleware
**Vulnerability:** The web server setup in `internal/bot/web.go` uses standard `http.ServeMux` and directly sets `http.Server.Handler` to `mux`. It lacks global security headers middleware (e.g., `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `X-XSS-Protection: 1; mode=block`, `Strict-Transport-Security`). This makes all web portal endpoints vulnerable to clickjacking, MIME-type sniffing, and potential XSS reflections, as well as leaving downgrade attacks open if HTTPS is enforced externally.
**Learning:** In Go `net/http`, standard mux doesn't have an easy "app.Use()" like Express. Global middleware requires wrapping the root `mux` inside another `http.Handler` before assigning it to `http.Server.Handler`. It was likely missed because handlers were added individually to `mux` rather than creating a global wrapping struct or function for the server.
**Prevention:** Always wrap the root `http.ServeMux` or router in a security header middleware before starting the server to ensure defense-in-depth on all endpoints, static and dynamic alike.
